# R3.4 Linear-Algebra Benchmark Foundation

R3.4 establishes a matched linear-algebra benchmark framework before the
encrypted BLAS layer is introduced.

## Terminology

The repository contains two distinct styles of encrypted matrix multiplication.

### Scalar encrypted GEMM

For `C = A B`, each output entry is evaluated as an encrypted dot product:

```text
C[i,j] = sum_k A[i,k] * B[k,j].
```

The current realistic RNS CKKS matrix methods follow this schedule:

- ciphertext/plaintext: one encrypted scalar multiplication per `(i,k,j)`,
  accumulate the dot product, then rescale each output;
- ciphertext/ciphertext: one encrypted scalar multiply/relinearize/rescale per
  `(i,k,j)`, then accumulate the resulting ciphertexts.

R3.4 calls these paths **scalar CP-GEMM** and **scalar CC-GEMM**.

### Matrix-structured CPMM / CCMM

The reference CPMM and CCMM constructions instead expose matrix structure at
the RLWE-component level.

For ciphertext/plaintext multiplication,

```text
(B, A) U = (B U, A U).
```

For ciphertext/ciphertext multiplication,

```text
(B, A) (D, C)
    -> (B D, B C + A D, A C),
```

followed by entrywise relinearization and CKKS rescaling.

R3.4 reserves the names **CPMM** and **CCMM** for these matrix-structured
constructions.

Historical binaries and result names are not renamed; the distinction applies
to new R3.4 experiments and later publications.

## Matched comparison

Each workload is described by

```text
M x K  multiplied by  K x N
```

and will ultimately be executed using:

1. cleartext reference GEMM/GEMV;
2. scalar CP-GEMM;
3. matrix-structured CPMM;
4. scalar CC-GEMM;
5. matrix-structured CCMM;
6. later packed/SIMD and BLAS-reduction backends.

The same deterministic input generator and cleartext oracle are used across
paths.

## Metrics

R3.4 records, as applicable:

- dimensions and batch count;
- wall-clock latency and throughput;
- scalar multiply/add counts;
- ciphertext/plaintext and ciphertext/ciphertext multiplication counts;
- relinearization and rescale counts;
- NTT/polynomial-operation counts where observable;
- ciphertext and plaintext counts;
- memory footprint;
- CKKS level and modulus consumption;
- maximum and mean numerical error;
- deterministic checksum for reproducibility.

Bootstrapping is outside the R3.4 kernel contract.

## R3.4 work packages

- R3.4a: semantics/API audit and terminology freeze.
- R3.4b: cleartext GEMM/GEMV reference and shape characterization.
- R3.4c: scalar encrypted CP/CC baselines.
- R3.4d: realistic matrix-structured CPMM/CCMM.
- R3.4e: matched comparison.
- R3.4f: application/tensor shape frontier and reproducibility freeze.

The cleartext reference introduced in R3.4b is intentionally dependency-free
and correctness-oriented. Optimized vendor BLAS is a later backend and should
not be conflated with this oracle.
