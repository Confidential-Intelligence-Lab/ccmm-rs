# R2.10 --- Realistic RNS/NTT CKKS Matrix-Multiplication Characterization

## Scope

R2.10 validates and characterizes the Roadmap-2 encrypted
matrix-multiplication path built on the leveled RNS CKKS implementation.

The realistic matrix layer uses:

-   `RnsCkksCiphertext`;
-   `RnsCkksCiphertextMatrix`;
-   `RnsCkksEvaluator`;
-   NTT-backed scalar multiply → relinearize → rescale;
-   ciphertext addition for dot-product accumulation;
-   canonical CKKS slot semantics;
-   `research-4096`.

The legacy coefficient-domain `ccmm()` implementation remains available
as a correctness/reference path and is not used for the R2.10 realistic
kernel measurements.

## Cryptographic scope

Profile:

``` text
PROFILE=research-4096
RING_DEGREE=4096
SLOT_COUNT=2048
CHAIN_LEVELS=3
TOTAL_MODULUS_BITS=105
INPUT_SCALE=2^35
```

The profile remains explicitly non-security-bearing.

Ciphertext encryption uses:

``` text
ErrorDistribution::DiscreteGaussian { sigma: 3.19 }
```

Evaluation-key generation uses:

``` text
noise_bound = 0
```

This is deliberate and preserves the R2.9 validated scope. The current
evaluation-key/relinearization construction is not yet noise viable with
Gaussian evaluation-key noise.

## Matrix algorithm

For square dimension `d`:

``` text
scalar CKKS multiply/relinearize/rescale operations = d^3
ciphertext additions                                = d^2(d-1)
multiplicative depth                                = 1
```

Each output ciphertext is:

``` text
C[i,j] = sum_k A[i,k] * B[k,j]
```

where each scalar multiplication is performed by the NTT-backed leveled
RNS CKKS evaluator.

## 2×2 reproducibility campaign

Five release-mode trials were executed at N=4096.

``` text
TRIALS=5
ALL_PASS=true

CCMM_US_MIN=518594.875
CCMM_US_MEAN=520023.1414
CCMM_US_MEDIAN=520241.791
CCMM_US_MAX=521630.708
```

Numerical results were identical across all five deterministic trials:

``` text
MAX_SLOT_ERROR=1.922629027223e-6
MEAN_SLOT_ERROR=8.527720653016e-9
RMS_SLOT_ERROR=5.041571872216e-8
```

The numerical acceptance threshold was:

``` text
MAX_SLOT_ERROR < 1e-3
```

Result: PASS.

## Scaling interpretation

Using the five-trial 2×2 mean as the baseline:

``` text
2x2 CCMM mean = 520023.1414 us
4x4 CCMM      = 4139224.417 us
```

Measured kernel scaling:

``` text
4139224.417 / 520023.1414 = 7.96x
```

The scalar multiplication count increases:

``` text
8 -> 64 = 8x
```

Therefore the measured CCMM kernel scales almost exactly with the
expected cubic work increase between 2×2 and 4×4.

The surrounding stages scale approximately quadratically with the number
of matrix entries:

``` text
encoding        ~3.87x
encryption      ~4.04x
decrypt/decode  ~4.01x
```

while the CCMM kernel scales approximately cubically:

``` text
CCMM kernel     ~7.96x
```

This is consistent with the implementation structure.

## Canonical-embedding note

The current canonical CKKS embedding implementation is a reference
O(N\^2) implementation.

For the 2×2 benchmark, canonical encoding takes approximately 1 second,
which is larger than the roughly 0.52-second encrypted CCMM kernel.

This encoding cost is reported separately and is not included in
`CCMM_US`.

Optimizing the canonical transform is therefore a future performance
opportunity and is not required for the R2.10 matrix-kernel
characterization.
