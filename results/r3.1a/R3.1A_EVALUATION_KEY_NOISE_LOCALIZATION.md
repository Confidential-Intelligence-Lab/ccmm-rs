# R3.1a — Evaluation-Key Noise Localization

## Result

R3.1a localizes the failure of Gaussian-noise multiplication keys in the
current RNS CRT-gadget relinearization construction.

For multiplication-key entry i,

    Dec(EK_i) = E_i * s^2 + e_i

and CRT gadget decomposition

    c2 = sum_i d_i * E_i mod Q,

the implemented relinearization satisfies

    Dec(Rel(c0,c1,c2))
      = c0 + c1*s + c2*s^2 + sum_i d_i*e_i mod Q.

The diagnostic verifies the identity

    e_relin = sum_i d_i*e_i

exactly on the research-4096 implementation.

## Conclusion

Changing only the CRT block partition does not make Gaussian evaluation-key
noise viable.

Even one-prime CRT blocks retain approximately 35-bit canonical residue
digits. Multiplication of these digits by small Gaussian evaluation-key
errors drives per-limb noise close to the modulus scale.

The current CRT-residue gadget therefore remains suitable for zero-noise
correctness and differential testing, but it is not an appropriate
security-bearing noisy evaluation-key construction at realistic parameters.

## Roadmap consequence

R3.1 proceeds with two new paths:

1. a signed bounded-base gadget as a transparent reference/noise oracle;
2. a hybrid P/Q key-switch construction as the candidate realistic
   security-bearing architecture.

The existing CRT-gadget implementation is retained unchanged as historical
and differential infrastructure.
