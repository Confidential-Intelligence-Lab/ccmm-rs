## Primitive split

### CPMM

Ciphertext-plaintext matrix multiplication evaluates:

```text
C = A_enc * U_plain
```

The RNS CKKS path preserves degree-one RLWE during plaintext multiplication.

Consequences:

```text
evaluation key required   false
relinearization required  false
```

The implementation accumulates each encrypted dot product and performs one
rescale per output element.

This makes CPMM the natural primitive for workloads where private encrypted
inputs are evaluated against public or server-held model parameters.

### CCMM

Ciphertext-ciphertext matrix multiplication evaluates:

```text
C = A_enc * B_enc
```

Each scalar multiplication produces a quadratic ciphertext and therefore uses
the R3.1 bounded-base Gaussian relinearization path before rescaling.

Consequences:

```text
evaluation key required   true
relinearization required  true
bounded base_log          20
ciphertext sigma          3.19
evaluation-key sigma      3.19
```

CCMM therefore supports collaborative computations in which both matrix
operands remain encrypted.

## Security and implementation boundary

Both application paths use the `research-4096` parameter set.

The underlying RLWE parameterization has a documented 128-bit classical target
under the retained R3.1 Lattice Estimator methodology.

The application claims remain intentionally narrower than a production-security
claim:

- the Gaussian sampler remains research infrastructure and is not hardened
  constant-time code;
- CCMM evaluation keys contain encryptions of secret-dependent values and retain
  the explicit circular/KDM assumption documented in R3.1;
- CPMM does not require evaluation keys and therefore does not introduce that
  evaluation-key assumption for its application path;
- implementation-level side-channel resistance and third-party cryptographic
  audit remain out of scope.

## R3.2 conclusion

R3.2 establishes two application-facing encrypted-computation modes over the
same realistic CKKS substrate:

```text
private data + plaintext model       -> CPMM
private data + private counterpart   -> CCMM
```

This is the application baseline for subsequent private-AI, depth,
packing, throughput, and accelerator studies.
