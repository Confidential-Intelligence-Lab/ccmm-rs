# R3.1b — Bounded-Base Noisy RNS Key Switching

## Objective

R3.1b replaces the CRT-residue gadget used by the original RNS
relinearization path with a balanced bounded-base decomposition.

The purpose is to avoid the evaluation-key noise amplification localized
in R3.1a while retaining exact RNS/NTT arithmetic semantics.

## R3.1b.1 — Exact bounded-base decomposition

For radix

    B = 2^w

each centered coefficient is represented as

    x = sum_j d_j B^j

with balanced signed digits satisfying

    |d_j| <= B / 2.

The research-4096 profile was validated for:

| base_log | Base | Digit count | Maximum observed digit |
|---:|---:|---:|---:|
| 4  | 16      | 27 | 8 |
| 8  | 256     | 14 | 128 |
| 12 | 4096    | 9  | 2048 |
| 16 | 65536   | 7  | 32766 |
| 20 | 1048576 | 6  | 524244 |

All decompositions reconstruct exactly.

## R3.1b.2 — Gaussian relinearization noise

Evaluation-key entries were generated using discrete Gaussian error with

    sigma = 3.19.

Observed maximum relinearization noise:

## R3.1b.3 — End-to-end noisy CKKS

Configuration:

    profile = research-4096
    ring degree = 4096
    slot count = 2048
    input scale = 2^35
    ciphertext error distribution = discrete Gaussian
    ciphertext sigma = 3.19
    evaluation-key error distribution = discrete Gaussian
    evaluation-key sigma = 3.19
    tolerance = 1e-3

Pipeline:

    encode

      -> NTT ciphertext multiplication
      -> bounded-base Gaussian relinearization
      -> CKKS rescale

## Conclusion

The bounded-base multiplication-key construction removes the noisy
evaluation-key failure mode present in the v2.0 CRT-gadget path.

At N=4096, Gaussian ciphertext noise and Gaussian evaluation-key noise
can coexist through ciphertext multiplication, relinearization,
rescaling, and canonical CKKS decoding while remaining comfortably
inside the current numerical tolerance.

The result establishes a viable noisy key-switch primitive.

It does not by itself establish a security-bearing CKKS profile.
Security designation still requires complete exposed-modulus accounting,
parameter selection, and lattice-estimator validation.

## R3.1b.4 — Statistical radix characterization

Ten deterministic but cryptographically distinct trials were executed for
each candidate radix. Ciphertext-encryption and evaluation-key randomness
were varied independently.

All 40 end-to-end CKKS executions passed the 1e-3 numerical tolerance.

For the N=4096 reference path, `base_log = 20` is selected as the
bounded-base operating point. It requires six evaluation-key entries,
has the lowest measured key-generation and relinearization cost among
the characterized candidates, and retains substantial numerical margin.

This selection is an engineering reference point for the current
research implementation. It is not by itself a security designation.
